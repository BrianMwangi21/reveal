### 4. Room Archival and Read-Only Mode

**Room Schema Updates** (`lib/models/Room.ts`):
- Added `expiresAt` Date field for archival
- Created MongoDB TTL index on `expiresAt` field with 0-second expiry
- Note: Removed `index: true` from field definition to prevent duplicate index warning

**Reveal API Update** (`app/api/rooms/[code]/reveal/route.ts`):
- Sets `expiresAt` to 7 days after reveal trigger
- Formula: `Date.now() + 7 * 24 * 60 * 60 * 1000`

**MongoDB TTL Index**:
- Automatic document deletion based on `expiresAt` field
- Runs every 60 seconds by default
- Simple, no external cron jobs needed
- Works on all MongoDB deployments including Atlas

**Read-Only Mode** (`app/rooms/[code]/page.tsx`):
- Activity Creator hidden when `isRevealed` is true
- Prevents new activity creation after reveal
- Bet, ClosestGuess, and Message components already handle read-only state

### 6. Next.js 15+ Compatibility Fixes

**params Promise Pattern:**
Multiple route handlers updated to handle Next.js 15+ params change:
- `app/rooms/[code]/layout.tsx`: `generateMetadata()` awaits params
- `app/api/rooms/[code]/download/route.ts`: GET handler awaits params
- All other routes already using Promise pattern

**Changed from:**
```typescript
{ params }: { params: { code: string } }
const code = params.code.toUpperCase();
```

**To:**
```typescript
{ params }: { params: Promise<{ code: string }> }
const { code } = await params;
const roomCode = code.toUpperCase();
```

**MongoDB Index Warning Fix:**
- Removed `index: true` from `expiresAt` field definition
- Kept `schema.index()` call which properly creates TTL index
- Eliminates "Duplicate schema index" warning

## Tech Decisions

1. **jsPDF**: Chosen for client-side/server-side PDF generation without external dependencies
2. **MongoDB TTL**: Simple, no-code solution for auto-deletion (no cron jobs needed)
3. **params Promise**: Properly implemented for Next.js 15+ async route params
4. **Share Messages**: Dynamic pre/post reveal messages for better social engagement
5. **Replay Button**: Independent function for clean code, not reusing initial effect
6. **Read-Only at Component Level**: Each component handles read-only state for flexibility
7. **PDF Generation on Server**: Better performance, no client-side processing
