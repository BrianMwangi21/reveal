# Session 07: Fix SSE Real-Time Reveal Sync

**Date:** 2026-01-04
**Session Goal:** Fix SSE real-time event broadcasting issue preventing guests from seeing reveal in real-time

## Problem Summary

Real-time reveal synchronization was broken. When the host triggered a reveal, only the host would see the countdown and reveal display. Guests would see nothing and had to refresh the page to see the updated state.

**Key Symptoms:**
- Host clicks "🎉 Reveal Now! 🎉" button → sees countdown and reveal
- Guests see nothing (no countdown, no reveal)
- Connection status shows "connected" (green) for all clients
- Guests must refresh to see the revealed state
- High number of concurrent server requests

## Root Cause Analysis

### The Real Issue: useSSE Hook Constant Reconnection

**Problem Location:** `app/hooks/useSSE.ts`

The `useSSE` hook had the `options` parameter in the `connect` function's dependency array:

```typescript
const connect = useCallback(() => {
  // ... setup code
}, [roomCode, guestId, nickname, options, maxRetries]); // ❌ options here!
```

**Why This Broke Everything:**
1. Parent component (room page) passes `options` as an inline object: `{ onRevealTriggered: () => {...}, ... }`
2. Every parent re-render creates a new `options` object with a new reference
3. New reference → `connect` dependency changes → `connect` function recreates
4. New `connect` function → `useEffect` in parent triggers again
5. `useEffect` closes old EventSource and opens a new one
6. This cycle repeats constantly → SSE connection never stabilizes
7. Events get lost because connection is constantly being recreated

**Result:** The SSE connection was unstable, causing event broadcasts to fail. Guests were essentially in a constant reconnection loop, missing the `reveal_triggered` event.

## Solution Applied

### 1. Stabilized Options Object with useRef

Moved `options` out of the dependency array and into a `useRef`:

```typescript
const optionsRef = useRef(options);

useEffect(() => {
  optionsRef.current = options;
}, [options]);

const connect = useCallback(() => {
  // ... setup
  eventSource.onmessage = (event) => {
    // ... parse event
    handleMessage(parsedEvent);  // Use stable callback instead
  };
}, [roomCode, guestId, nickname, handleMessage]); // ✅ No options!
```

**Key Changes:**
- Removed `options` from dependency array
- Created `optionsRef` to store latest options
- Updated effects with `useEffect` to sync ref
- Used memoized `handleMessage` callback instead of inline options handlers
- Used `connectRef` to properly handle error reconnection without closure issues

### 2. Event Message Handler Extraction

Extracted message handling to a stable callback to avoid "any" type issues:

```typescript
const handleMessage = useCallback((parsedEvent: SSEEvent) => {
  switch (parsedEvent.type) {
    case 'reveal_triggered':
      optionsRef.current.onRevealTriggered?.(parsedEvent.data as Parameters<NonNullable<typeof optionsRef.current.onRevealTriggered>>[0]);
      break;
    // ... other cases
  }
}, []);
```

### 3. Fixed Ref Assignment for Reconnection

Used proper `useEffect` to assign `connect` function to ref for error handling:

```typescript
useEffect(() => {
  connectRef.current = connect;
}, [connect]);
```

This allows the `onerror` handler to call the latest `connect` function without closure issues.

## Key Insights

**The Power of Dependency Arrays:** This bug highlights how critical React's dependency arrays are. A single `options` parameter in the wrong place caused the entire SSE real-time system to break silently. The connection "seemed" to work (green indicator) but was fundamentally unstable.

**Object Reference Stability:** In React hooks, object parameters should NEVER be in dependency arrays unless you explicitly want to retrigger effects when the object changes. Always use refs for mutable data that shouldn't trigger recreations.

**Real-Time Debugging:** The fact that the system appeared to work (connections showed "connected") but actually wasn't is a classic real-time bug. The solution required understanding the entire event flow rather than just logging.
