### 4. Room Settings API Endpoint

**PUT Endpoint** (`app/api/rooms/[code]/route.ts`):
- New `updateRoomSchema` with Zod validation:
  - `guestId` (required) - for host verification
  - `name` (optional, string, 1-100 chars)
  - `revealTime` (optional, datetime string)
  - `revealType` (optional, enum of reveal types)
  - `revealContent` (optional, object with type, value, caption)
- Host verification: compares `room.host.id` with provided `guestId`
- Status check: prevents updates after room is revealed
- Validation: reveal time must be in the future
- Partial updates supported via `updates` object
- SSE broadcast when reveal time changes

## Tech Decisions

1. **Per-Room Dashboard**: Each room has its own dashboard at `/rooms/[code]/dashboard`
   - Simpler than multi-room dashboard
   - Matches "dispensable rooms" use case
   - No need for user accounts

2. **Analytics Calculation**: Client-side fetching and calculation
   - Simpler than server-side aggregation
   - Real-time updates via SSE
   - Scales well for single-room use case

3. **Partial Updates**: PUT endpoint supports partial updates
   - Allows updating specific fields without affecting others
   - More flexible API design
   - Follows PATCH-like semantics with PUT method

4. **Time Change Warning**: Yellow banner in settings modal
   - Alert host that change will notify all guests
   - Prevents accidental changes
   - Good UX pattern for important actions

5. **SSE for Time Changes**: Real-time guest updates
   - Guests see new time immediately
   - No need to refresh
   - Consistent with other SSE events
